## Document boundary

Screen and paper are separate representations. `PrintDocument` receives a typed business model; it never copies the page DOM or screen table. The runtime mounts only this document inside a temporary, same-origin sandboxed iframe and calls that frame's print API. The parent application is never printed by migrated routes. The frame is removed on `afterprint` (print or cancel), preparation failure, or expiry.

`PrintDocumentModel` in `apps/web/src/lib/print.ts` supports REPORT, REGISTER and DOCUMENT; title, subtitle, business document number, company/branch, organization fields, author, actual generation timestamp/timezone, optional date boundaries, applied filters, compact metrics, document metadata, table sections, totals, notes, section page breaks, A4 portrait/landscape and an explicit dataset-scope label.

Components: PrintDocument, PrintHeader, PrintContextBlock, PrintFilterSummary, PrintSummaryMetrics, PrintTable, PrintEmptyState and PrintFooter. Dates, times, quantities, currency, percentages and durations share `printFormatters`. Missing values use an em dash; invalid numeric/date values never become `NaN` or `Invalid Date`.

## Identity and scope

Company/branch labels come from the authenticated operational context, including archive context when selected. A scope key includes user, company, branch, organizational scope, context version and archive mode. Missing context/user or a context change aborts printing. Leaving the route while preparation is pending also aborts. No new permission or backend endpoint exists; the existing report API remains authoritative.

Labels never substitute technical IDs. Company identity is required. Branch, author, date boundaries, optional metadata and filter sections are omitted when absent. `printedAt` is refreshed immediately before mounting the print document; filter dates and record dates cannot supply the print timestamp. Calendar date filters are formatted without shifting their day through UTC conversion. Runtime timezone comes from the application environment's Intl convention.

Numeric dates/times and business document numbers explicitly use LTR isolation inside either document direction. The date formatter removes locale-added directional separator marks so day/month/year groups remain one readable sequence. Date columns reserve sufficient width for the optional eighth reference column. PDF inspection checks complete rendered date strings and exactly one occurrence of every multi-page fixture number, in addition to paper bounds.

## Tables and paper

Every table declares print columns independently: stable key, localized label, explicit value/formatter, alignment, importance and relative width. Screen-only columns are excluded. Print-only columns are supported. No action elements or application controls are rendered. Text is escaped by React and wraps without clipping; headers repeat through semantic thead, rows avoid breaks, and explicit section breaks are available.

A4 portrait is the reference default. Landscape is allowed only after a separate business-column review shows portrait is insufficient. Relative column weights reserve space for business identity. Metadata uses two balanced columns; compact metrics use equal cells. Black text, readable borders and textual statuses preserve grayscale meaning. The footer contains system identity and print timestamp. Automatic page numbering is not asserted where browser support is uncertain. No new logo was invented.

## Dataset policy

Maintenance Requests prints ALL_FILTERED_RESULTS, up to 500 rows, through at most five sequential reads of 100 rows. It never silently truncates or prints UI page one as a full report. Totals, page size/count, expected row counts and duplicate identities are checked. Errors or detected changes abort before opening the frame and use the existing localized error dialog. These checks do not create a database snapshot; concurrent edits that preserve total/order/identity may remain undetected. A future stronger snapshot contract requires a separately reviewed API change.

Filters and readable lookup labels are snapshotted only with a successful screen fetch. Later unsubmitted values cannot change the printed summary. Print collection uses that snapshot. No unlimited fetch, schema change, database write, new role or lifecycle change is part of this standard.

## Operational DOCUMENT mode

Operational documents use the same engine as reports; they are not a second print path. A DOCUMENT model prints one business artifact identified by its business number and read from its canonical detail endpoint at print time. The Maintenance Work Order reference (`/admin/maintenance/work-orders/[id]`) re-reads `GET /maintenance-work-orders/:id`, prints company/branch from the authenticated context, and includes only an explicit allowlist of business fields: identity, status/type/priority/scope, machine/line/component/cost center/work location/source request/warehouse, assignments, planned/actual dates, parts with per-line unit and issue status, and cost entries.

The Repair Order document (`/admin/maintenance/repair-orders/[id]`) follows the same contract with `GET /maintenance/repair-orders/:id` and the existing `repair-orders:read`: repair-order number, spare-part code/name, condition/quantities, warehouse/machine/component/source request, external-repair provider, lifecycle dates, inspection/failure/repair/test narrative, action table and a conditional cost summary. The existing Maintenance Request document is reused unchanged (`EXISTING_DOCUMENT_REUSED`); Tasks is classified `NOT_PRINTABLE` because the persisted execution record has no business number and sourced executions are covered by the request/work-order document.

The Inventory Opening Balance document (`/admin/inventory/opening-balances/[id]`) re-reads `GET /inventory/opening-balances/:id` with the existing `inventory:opening-balance:read` and prints the business number, localized status, company/branch/warehouse, dates, reason, line count, product code/name, recorded quantity with the product unit, optional canonical unit cost/currency and notes. It prints no computed line value, document total, mixed-UOM sum, location, lot or user identity; the canonical detail supplies no readable location/lot/user names, so those fields are omitted rather than replaced with IDs. A zero-line document renders a localized empty state for legacy data.

The Inventory Movement document (`/admin/inventory/movements/[id]`) re-reads `GET /inventory/movements/:id` with the existing `inventory-movement:read` and prints the movement number, localized movement type and status, company/branch, the one movement warehouse, movement/posted/cancelled/created/updated dates, localized source type, line count, product code/name, transaction quantity with the recorded line unit, per-line IN/OUT direction, and optional canonical batch, serial, expiry, unit cost, total cost and currency plus notes. The canonical movement is single-warehouse with per-line direction; there is no header direction and no source/destination warehouse pair, so no empty warehouse pair is printed. The contract exposes a source type but no referenced business document number, so the reference is identified by type only; warehouse-location names and readable user names are omitted rather than replaced with IDs. No document quantity total or valuation is computed. Print re-reads the canonical detail; `PERMISSION_CHANGE = 0`.

The Inventory Ledger register (`/admin/inventory/ledger`, `inventory-ledger:read`) is **implemented** as a thin route-specific wrapper over the shared InventoryMovement register model, not a second register. `inventory-movement-register-print.ts` owns the six business columns (movement number, date, localized movement type, readable warehouse, status, notes), the movement-count summary, redaction and notes; `inventory-ledger-register-print.ts` supplies the `inventoryLedger.title` title and applied filter metadata. Mode is `REGISTER`, A4 portrait, and Print/PDF share the same model. All applied filtered rows are collected through `collectPrintRows` at 100 per page with a 500-row cap; 501 is blocked with the localized narrow-filters error and never emitted as a partial document. Pagination is deterministic (`movementDate desc, id desc`) and a date-only `dateTo` includes the whole day. The ledger route keeps `inventory-ledger:read`; the reports route keeps `reports.inventory:read`; `PERMISSION_CHANGE = 0` and no print permission exists. It never prints product/quantity/UOM columns, mixed-UOM totals, running/opening/closing balances, valuation, raw ids/`sourceId`, actor ids, `lockVersion`, `requestId`, `_count` or secrets. `EXISTING_MOVEMENTS_REGISTER_REGRESSION = PASS`. See `docs/proofs/inventory-ledger-register-print-2026-11-13.md`.

The Inventory Count document (`/admin/inventory/counts/[id]`) prints the navigation-integrated `InventoryCount` family. It re-reads the count-scoped `GET /inventory/counts/:id/results` with the existing `inventory-count:read`; that read delegates to the same `findOne` company/branch/warehouse scope and is the only authorized count read that also returns the recorded product unit (the legacy `/:id` select omits it, and a backend contract change is out of scope). It prints the count number, localized count and line statuses, company/branch/warehouse, count/started/completed/cancelled/created/updated dates, line/product/verified counts, product code/name, the stored count-time system quantity, counted quantity, the recorded difference with the domain sign (`countedQty - systemQty`), the recorded product unit, readable location, line notes and notes. The stored `systemQty` snapshot is never replaced by a current `InventoryBalance` and the difference is never recalculated. Cost, currency, lot/batch/serial, counter/verifier identities, mixed-UOM totals and valuation are never printed. `BLIND_COUNT_MODEL = NOT_SUPPORTED`: the workflow has no blind/hidden-expected/variance-mask/recount/multi-counter mode and the authorized screen already shows these values to `inventory-count:read` holders, so print visibility equals authorized UI visibility. The second `InventoryPhysicalCount` family (`/admin/inventory/physical-counts`) is a separate deferred workflow and is not printed, to avoid duplicate count-document families. Print re-reads the canonical count source; `PERMISSION_CHANGE = 0`.

Amounts print as numbers unless the canonical contract supplies a currency (the Opening Balance and Movement lines supply an optional `currencyCode`); quantities are never totalled across mixed or missing units. No CUID, internal `id`, `companyId`, `branchId`, `createdById`, `lockVersion`, raw foreign key, action, control or application chrome is printed. Missing values are a dash, never a silent zero. The classifier and approval gate live in `ATsoftERP-operational-print-justification.md`.

The Inventory Adjustment document (legacy `InventoryAdjustment`, `/admin/inventory/adjustments/[id]`, `inventory-adjustment:read`) is **implemented** on the shared print engine as `inventory-adjustment-document-print.ts`, with a Print action on the detail page that re-reads the canonical detail at print time. Decision: `INVENTORY_ADJUSTMENT_AUTOMATED_COMPLETE_NATIVE_NOT_VERIFIED` (automated model gate PASS, PDF structural gate PASS, native preview/Save-as-PDF/cancellation/paper NOT_VERIFIED). The canonical detail returns the business number, status, reason, dates, warehouse, optional linked count number and lines with stored `systemQty`, `countedQty`, recorded `differenceQty`, `product { id, name, code, unit }` and readable `warehouseLocation { id, code, name }`; the read-contract enrichment was additive only. The document prints the stored historical snapshot and recorded difference sign, never a live balance or derived after-quantity, and omits cost/valuation, movement reference, lot/batch/serial and raw ids; quantities with unlike units are never summed. See `docs/proofs/inventory-adjustment-document-print-2026-11-13.md`.

The Inventory Stock Adjustment document (`InventoryStockAdjustment`, `/admin/inventory/stock-adjustments/[id]`, `inventory:stock-adjustment:read`) is **implemented** as `inventory-stock-adjustment-document-print.ts` on a new read-only detail page whose Print action re-reads `GET /inventory/stock-adjustments/:id` at print time. Decision: `STOCK_ADJUSTMENT_AUTOMATED_COMPLETE_NATIVE_NOT_VERIFIED` (automated model gate PASS, PDF structural gate PASS, native preview/Save-as-PDF/cancellation/paper NOT_VERIFIED). It prints the business `code`, localized status, document date, reason, company/branch, `[code] name` warehouse, workflow timestamps, product code/name, the stored `adjustmentType` direction, the recorded positive quantity with the source product unit, conditional recorded unit cost/currency/valuation reason/line notes, document notes and runtime print metadata. It never derives direction from the quantity sign, negates quantities, reads a live `InventoryBalance`, derives before/after quantities, prints a readable location or movement business reference (neither is exposed by the canonical detail), computes a line value/document total/valuation, or prints workflow actor identities and raw ids. `BEFORE_QTY_HISTORICAL_INTEGRITY = NOT_APPLICABLE`, `AFTER_QTY = OMITTED_NOT_STORED`, `LOCATION = NOT_APPLICABLE`, `MOVEMENT_REFERENCE = OMITTED_SOURCE_NOT_READABLE`; summary is line count only. See `docs/proofs/inventory-stock-adjustment-document-print-2026-11-13.md`.

## Print and PDF actions

The reference action bar and ReportExportButton use the same preparation function and business model. PDF means the browser's Save as PDF destination through this document print dialog; it is not an independently downloaded PDF endpoint. CSV remains the existing tabular export.

Unmigrated report routes retain their legacy behavior until their own gate passes. In particular the shared export component still has a legacy host-print fallback for callers without `onPrint`; this is tracked unfinished rollout, not certification of those pages. Barcode/label dimensions and specialized flows remain unchanged.
