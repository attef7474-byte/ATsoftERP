# ATsoftERP print audit

Audit baseline: main @ 54e3706f98c8ff7aa7f48febe12611015c3e29fe, 2026-11-10. Existing employee-save and LAN-login repairs are preserved. Presentation-only scope; no database, lifecycle, permissions or context-policy changes.

## Execution contract

Inventory first; build a shared document engine; prove maintenance requests in AR/EN and paper/PDF before migrating other reports; then evaluate operational registers/documents. No Git writes. Existing worktree captured in .tmp/unified-print/initial-git-status.txt and hashed in preexisting-files.json.

## Findings

The existing lib/print.ts is empty. Report actions call window.print() on the application window. ReportExportButton's PDF button does the same. ReportPageShell has no dedicated print representation. The maintenance request detail /print route has a business body but is nested in AdminShell and still prints its host window. Barcode flows generate specialized label HTML in separate windows; preserve their dimensions and behavior. No react-to-print dependency.

Standard analytical report endpoints return rows/cards/total/page/pageSize/totalPages, generally at 20 rows. Their pagination helper has no maximum; the client print adapter must enforce a finite limit and fail visibly rather than silently truncate. Cost report combines two individually paginated sources and requires a dedicated pagination review before all-results printing. Overview/KPI/operations datasets are aggregates, not generic row lists. API authorization and tenant filters remain authoritative.

Production and inventory products pages delegate to existing workspace/panel components; absence of a table in page.tsx does not make them non-printable. Classification below reflects business purpose, not a recommendation to add a button to every page. Operational transaction lists require a selected document and canonical line-items data; a generic register is not an adequate transaction printout.

Navigation-only report hub is NOT_PRINTABLE. Existing label routes are LABEL_PRINTING_SPECIAL_CASE. The existing request detail print route is ALREADY_DEDICATED_PRINT_FLOW but still requires isolation remediation.
