# برومبت التنفيذ المرجعي — ATsoft ERP Reference Implementation Prompt

**الإصدار:** 1.0  
**الغرض:** قالب موحد لبرومبت تنفيذ أي ميزة أو إصلاح أو تحسين في ATsofterp. يستخدمه المهندس أو المؤشر الاصطناعي عند بدء مهمة تنفيذ.

---

## 1. الغرض والنطاق

أكمل المهمة التالية في مستودع `ATsofterp` وفقًا للدستور الهندسي:

> **[أدخل وصف الميزة أو الإصلاح هنا — ماذا يريد المستخدم، ولماذا، وما النطاق المطلوب]**

**النطاق (اختر):**
- [ ] ترحيل schema آمن
- [ ] backend (service/controller/DTO/validation/permission)
- [ ] frontend (page/component/form/i18n)
- [ ] اختبارات
- [ ] تقرير إثبات
- [ ] إصلاح عطل

## 2. قبل التنفيذ (أمر إلزامي)

1. اقرأ `docs/architecture/atsoft-erp-engineering-constitution-v1.0.md`.
2. اقرأ ملفات القواعد ذات الصلة من `docs/agent-rules/`.
3. سجّل الحالة الحالية: الفرع، والالتزام، والملفات المعدلة، والملفات غير المتعقبة.
4. افحص الكود القائم ذي الصلة (لا تعامل المستودع كمشروع جديد).
5. حدد التطبيقات المكررة أو القديمة قبل إنشاء ملفات جديدة.
6. حدد أصغر حدود تنفيذ آمنة تحقق النتيجة كاملة.

## 3. قواعد إلزامية (لا تتجاوز دون اعتماد صريح)

- لا بيانات مزيفة، ولا صفحات وهمية، ولا أزرار بلا معالجات.
- فرض عزل الشركة/الفرع في الـ backend لكل عملية.
- لا تعتمد على header أو حقل مخفي من العميل.
- استخدام `POST` للإنشاء و`PATCH /:id` للتحديث.
- نماذج قاعدة البيانات: ترحيل آمن nullable → backfill → constraints.
- استخدم `Decimal` للنقود والكميات، ومعاملات ذرية للمخزون والتكلفة.
- لا تُعدّل رصيد المخزون دون معاملة مصدر مصرح بها.
- كل إجراء حساس يُدقق (المستخدم، والشركة، والفرع، والكيان، والوقت، والقيم، والسبب عند الحاجة).
- ترجمات عربية وإنجليزية متزامنة، مع RTL/LTR.
- لا مفاتيح ترجمة خام للمستخدم.
- صلاحية كاملة: معرّفة ومُبذورة ومُفرضة في backend ومستخدمة في frontend ومترجمة ومختبرة.
- اختبارات ذات معنى: وحدة، تكامل، مستأجر، صلاحية، انتقال حالة، إرسال مكرر، مرجع غير صالح.
- لا تخطّ اختبارات، ولا تحذف اختبارات لتمرير البناء، ولا تضعف التأكيدات.

## 4. ترتيب التنفيذ

1. تحقق من الـ schema والترحيل إن لزم.
2. نفّذ الـ backend (DTO، خدمة، تحكم، صلاحية، تدقيق).
3. نفّذ الـ frontend (صفحات/مكونات/نماذج/i18n).
4. أضف الاختبارات.
5. نفّذ التحقق (المادة 20 في الدستور).
6. أثبت التشغيل الحقيقي (المادة 21).
7. راجع الـ diff النهائي.
8. أبلغ بالنتائج وفق المادة 26.

## 5. الالتزام والدفع

لا تنفّذ أي عملية كتابة Git ما لم تطلبها المهمة صراحةً. عند طلبها: راجع `git status` و`git diff` أولاً، والتزم فقط الملفات المقصودة، ولا تُدرج أسراراً أو مخرجات بناء، ولا تدفع قسراً.

## 6. الإخراج المطلوب

أبلغ في النهاية:

1. الحالة (`COMPLETE` / `PARTIAL` / `BLOCKED` / `NOT_VERIFIED`).
2. النطاق الدقيق المكتمل.
3. الملفات المضافة/المعدلة.
4. نماذج/ترحيحات قاعدة البيانات.
5. نقاط نهاية API ومسارات frontend.
6. الصلاحيات المضافة.
7. الاختبارات المضافة والنتائج.
8. نتائج البناء والتحقق.
9. الإثبات التشغيلي وعزل المستأجر.
10. القيود المعروفة والمشكلات المسبقة.
11. حالة Git.
